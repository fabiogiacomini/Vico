# Contributing

Vico's original code is licensed under MIT. Submit original-code contributions under that license and preserve applicable copyright and third-party notices. All new dependencies need a compatibility review before integration.

Write clear English. Link changes to feature IDs and acceptance scenarios in `docs/implementation-plan.md`. Keep private outing data separate from public source records. Use synthetic fixtures, never personal tracks, credentials or group histories.

Run `pnpm check`, `pnpm registry:check` and platform exports before proposing a change. Add tests for meaningful safety, lifecycle and data-state behavior. Do not add tests that only repeat UI implementation details. Native changes also need device evidence.

A source proposal needs metric meaning, coverage, timestamps, reuse rights, attribution, cadence, quotas and failure behavior. Start as a candidate. Do not switch it to active until a reviewed recent-record test and bounded pilot are documented.

Never add private data to logs or push payloads. Do not invent crowds, map coverage, walking paths or encryption status. Translations may be introduced later; the current interface is English only by product-owner decision.
